API Reference

The entire public API lives on the Alohomora singleton. Every method is mirrored as a no-op in the release artifact.

Recording

Methods for capturing data from your running app. All are fire-and-forget on a background dispatcher.

recordEvent(name, properties?)

Record a named event with optional key-value properties. Appears in the Events timeline.

recordError(throwable, place?)

Record a caught exception. Swift: recordError(reason, stackTrace?, place?). Uncaught exceptions are captured automatically via the crash handler.

recordTraffic(status, url, method, ...)

Manually record a network request for clients Alohomora doesn't auto-capture. Use OkHttp/Ktor interceptors instead when possible.

recordSpan(traceId, spanId, ...)

Record a distributed trace span. Short form: recordSpan(name, durationNanos). See Traces for adapters.

recordFeatureFlag(key, value, ...)

Record a single feature flag with source, type, and metadata. Batch: setFeatureFlags(flags, source?).

registerAppDatabase(name, path?)

Register an app database for live inspection in the Database panel. Supports Room and raw SQLite.

excludeAppDatabase(name)

Exclude a database from inspection. Useful for internal databases you don't want cluttering the panel.

clearAppDatabaseOverrides()

Clear all database registration overrides, reverting to auto-discovered databases.

setShakeToOpenEnabled(enabled)

Toggle shake-to-open for the in-app console. Default: on.

redactHeaders(vararg headerNames)

Mark headers for redaction at capture time. Values are replaced with [REDACTED] before reaching the database. Case-insensitive.

clearRedactedHeaders()

Remove all header redaction rules. New traffic captures will include full header values again.

registerSharedPreferences(name, reader)

Register a custom SharedPreferences reader (e.g. EncryptedSharedPreferences). The reader lambda returns Map<String, Any?> and is called on-demand.

unregisterSharedPreferences(name)

Remove a previously registered SharedPreferences reader.

clearSharedPreferencesOverrides()

Remove all custom SharedPreferences registrations, reverting to auto-discovered stores.

setDebugConfig(key, value)

Store a debug key-value pair that survives app restarts. Backed by SharedPreferences (Android) or NSUserDefaults (iOS) under an Alohomora-private namespace.

getDebugConfig(key): String?

Retrieve a previously stored debug config value. Returns null if not set.

removeDebugConfig(key)

Delete a debug config entry.

Traffic Replay

Edit and re-send captured traffic through your app's own HTTP client. Alohomora never sends it directly — the request goes back through your interceptors so signatures, auth tokens, and other derived headers are regenerated. See Features › Traffic Replay for setup examples.

registerReplayHandler(handler)

Register a handler for traffic replay. Accepts an OkHttp, Ktor, or custom handler. The replay action appears in both consoles once registered.

clearReplayHandler()

Remove the registered replay handler. The replay action disappears from both consoles.

isReplaySupported

true if a replay handler is registered. Always false in the noop artifact.

ReplayOutcomes.sent(traceId?)

Factory for a successful replay result. Use from Swift where sealed class subtypes are not exported. traceId is optional.

ReplayOutcomes.failed(reason)

Factory for a failed replay result. Pass a human-readable error description.

Header Stripping

Fine-tune replay behaviour for apps with custom authentication or signing headers.

ReplayHeaders.additionalStripList

Set of header names to strip before replay. Add custom signature or auth headers here so your interceptors regenerate them. Content-Length, Host, and [REDACTED] values are always stripped.

Kotlin
// Strip custom signature headers before replay
ReplayHeaders.additionalStripList = setOf(
    "X-Signature",
    "X-Request-Id",
    "X-Timestamp"
)
Blocked requests: Replay is hidden for requests with truncated or multipart bodies, and for entries where the body could not be parsed. TrafficEntry.replayBlockedReason() exposes the reason.

Infrastructure

Lifecycle and server management.

init()

Initialize Alohomora. Android auto-initializes via AndroidX Startup and needs no call. iOS requires manual: Alohomora.shared.doInit() in Swift.

startDevToolsServer(port?)

Start the TCP server for the desktop companion. Default port: 53999. Called automatically on Android; call manually on iOS.

stopDevToolsServer()

Stop the TCP server and drop the active connection.

Plugins

Embed custom Compose screens into Alohomora's navigation via CustomScreenPlugin. Plugins can expose editable data fields and actions to the desktop companion.

registerPlugin(plugin)

Register a CustomScreenPlugin to add a custom tab to the console. The plugin provides an ID, display name, icon, and a @Composable Content() block.

unregisterPlugin(pluginId)

Remove a plugin by its ID. The tab disappears from navigation.

getPlugins()

Returns the list of currently registered plugins.

registerAction(id, label, ...)

Register a standalone DevTools action with an optional description, parameters, and a DevToolsActionHandler. Actions appear in the desktop companion and can be triggered remotely.

unregisterAction(id)

Remove a previously registered standalone action.

publishPluginData(pluginId)

Push updated data field values to the desktop companion after state changes. Call this after mutating the backing state of a plugin's dataFields.

Data Fields

Plugins can expose key-value data via the dataFields property. Each PluginDataField carries a key, display label, type, a value lambda for the current value, and an optional onUpdate handler for edits from the desktop.

Kotlin
class EnvironmentPlugin : CustomScreenPlugin {
    override val id = "environment"
    override val title = "Environment"
    override val showInDashboard = true

    override val dataFields = listOf(
        PluginDataField(
            key = "backend_url",
            label = "Backend URL",
            value = { AppConfig.backendUrl },
            onUpdate = PluginDataUpdateHandler { newUrl ->
                AppConfig.backendUrl = newUrl
            }
        ),
        PluginDataField(
            key = "env",
            label = "Environment",
            value = { AppConfig.environment },
            options = listOf("dev", "staging", "prod"),
            onUpdate = PluginDataUpdateHandler { env ->
                AppConfig.environment = env
            }
        )
    )

    @Composable override fun Content() {
        // Your custom screen UI
    }
}

After changing state, call Alohomora.publishPluginData("environment") to push the new values to the desktop.

Custom Actions

Plugins can expose actions via the actions property, or register standalone actions outside a plugin:

Kotlin
// Standalone action (no plugin needed)
Alohomora.registerAction(
    id = "clear_user_cache",
    label = "Clear User Cache",
    description = "Wipe the local user profile cache"
) { params ->
    userCache.clear()
    mapOf("status" to "cleared")
}

Actions can accept parameters via ActionParameter (name, type, label, required, options). The handler receives parameters as Map<String, String> and returns a result map.

NativeScreenPlugin (iOS)

On iOS, wrap a native UIViewController as a plugin using NativeScreenPlugin:

Kotlin (iOS)
Alohomora.registerPlugin(
    NativeScreenPlugin(
        id = "native_debug",
        title = "Native Debug",
        viewControllerProvider = NativeScreenViewControllerProvider {
            MyNativeDebugViewController()
        }
    )
)

The view controller is wrapped in Compose via UIKitViewController interop. All standard plugin properties (icon, priority, dataFields, actions) are supported.
